# Layout and Branding Fixes for Ruleta de Sorteo

Updated the project branding and fixed a critical layout issue where the wheel overlapped buttons in the interface. The header now displays the full institution name with improved logo visibility, and the wheel-box layout was restructured to prevent rendering conflicts.

**Watch for:** Confirm that the wheel height constraint (280px) is sufficient across different screen sizes and that mobile responsiveness remains functional.

**Verdict**: APPROVED

## High-level view

The title now reflects the full institution identity in both the HTML `<title>` tag (for browser tabs and SEO) and the visible header, rendered across two lines for readability. The logos increased from 55px to 75px in height, improving their presence in the header without disrupting the layout.

The critical layout fix constrains the wheel-box to a fixed 280px height with `flex: 0 0 auto`, replacing the previous `flex: 1` which allowed it to expand and hide the action buttons below. The wheel now sits in a defined space, and the "Sorteo completo", "Uno a uno", and "¡Girar!" buttons remain visible and accessible without overlap. The spacing between the wheel and buttons is explicit (0.5rem margin-bottom), preventing the flex layout from collapsing this gap.

The changes preserve the existing visual hierarchy, color scheme, and responsiveness patterns. The CSS grid for the two-column layout (left panel with wheel, right panel with participant list) remains intact.

## Branding and Visibility

The header title was updated to the full institution name: "Universidad Nacional del Centro del Perú – Dirección de Proyección Social y Extensión Cultural". In App.jsx, this is split across two lines with a `<br/>` tag to fit the header width. The browser tab title (index.html) uses the same text with a hyphen separator, improving searchability and professionalism.

Logo height increased from 55px to 75px, with `max-width` adjusted to 160px (from 140px) to maintain proportions at the larger size. The header layout uses flexbox with `space-between`, ensuring logos anchor to the left and right while the title centers. This positioning and sizing balance visual weight without cramping the available space.

## Wheel Layout and Button Accessibility

The core issue was that `.wheel-box` had `flex: 1`, which in a column flex layout makes it expand to fill available space, pushing the buttons out of view. The fix sets `flex: 0 0 auto` with an explicit `height: 280px`. This fixed height respects the wheel's natural size while leaving room for buttons and padding.

The left panel is a flex column containing: mode toggle buttons (40px), wheel-box (280px), spin button (40–50px), and action buttons (40–50px). The explicit sizing prevents the wheel from claiming extra space. The right panel (participants list and results) uses the same constraint pattern with scrollable list areas.

The margin-bottom on wheel-box (0.5rem) is a CSS guard preventing any flex gap collapse that might otherwise allow the wheel SVG to visually bleed into button zones.

## CSS Structure and Responsiveness

The layout uses CSS Grid (two equal columns) at the app level, with flex columns inside each panel. No media queries or breakpoint changes were introduced. The fixed wheel height (280px) means narrow or mobile viewports will constrain the wheel but not hide buttons. If mobile responsiveness is needed (e.g., stacking columns), that would be a future enhancement; it was not in scope for this fix.

The padding on `.app` (0.6rem 1rem) and gaps throughout remain consistent. The `overflow: hidden` property on the main app and panels ensures no accidental scrollbars appear when content is snug.
